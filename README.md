# Лабораторная работа 2. Вариант 26 — Городские обращения о благоустройстве

REST API на **Spring Boot 3.5.6, Maven, Java 21**. Данные хранятся в памяти (коллекции),
после перезапуска приложение начинает с пустых данных.

## Запуск
```
mvn spring-boot:run
```
Сервер: http://localhost:8080

## Ресурсы
| URL | Сущность | Поля |
|---|---|---|
| `/api/city-objects` | Городской объект | адрес, тип объекта, состояние |
| `/api/city-reports` | Обращение | объект, автор (User), описание проблемы, статус |
| `/api/work-crews` | Рабочая бригада | название, поддерживаемые типы объектов, лимит активных работ |
| `/api/work-orders` | Наряд на работу | обращение, бригада, срок, статус, описание результата |
| `/api/users` | Пользователь | username, ФИО, email |

Для каждого ресурса:

| Операция | Метод | Ответ |
|---|---|---|
| Список | `GET /api/{resources}` | 200 + массив |
| По id | `GET /api/{resources}/{id}` | 200 + объект / 404 |
| Создание | `POST /api/{resources}` | 201 + объект с `id` |
| Обновление | `PATCH /api/{resources}/{id}` | 200 + объект |
| Удаление | `DELETE /api/{resources}/{id}` | 204 |

## Архитектура
- `controller/` — обработка HTTP-запросов и маппинг DTO ↔ модель;
- `service/` — бизнес-логика и проверки;
- `repository/` — хранилище (`ConcurrentHashMap`);
- `dto/` — входные/выходные модели с валидацией;
- `exception/` — единый обработчик ошибок.

## Бизнес-правила
- Новое обращение всегда `NEW`, новый наряд всегда `PLANNED` (статус при создании задаёт сервер).
- Наряд выдаётся только бригаде, поддерживающей тип объекта, и только в пределах её лимита активных работ.
- Переходы наряда: `PLANNED → IN_PROGRESS / DONE / CANCELLED`, `IN_PROGRESS → DONE / CANCELLED`.
- При `DONE` обязателен `resultDescription`, сервер ставит `completedAt`, обращение становится `RESOLVED`.
- Удаление каскадное (пользователь/объект → обращения → наряды; бригада → наряды): недействительных ссылок не остаётся.
- Текущее время (`createdAt`, `updatedAt`, `completedAt`, «сегодня» для срока) берётся только с сервера.

## Безопасность
- Неизвестные поля в JSON → 400 (нельзя подменить `id`, `createdAt`, статус).
- Валидация входных данных (`@NotBlank`, `@Size`, `@Pattern`, `@Email`, `@Positive`).
- Ошибки возвращаются в едином формате без стек-трейсов.
- Операции записи синхронизированы — лимит бригады нельзя обойти параллельными запросами.
